# ارتقای مرحلهٔ اول خورشید

> حافظه و پایداری مسیر Live در [مرحلهٔ دوم](UPGRADE_PHASE2_FA.md) ارتقا یافته‌اند. فهرست کارهای باقی‌ماندهٔ آن گزارش، وضعیت جدیدتر را نشان می‌دهد.

تاریخ: ۲۰۲۶-۱۰-۱۷. این مرحله زیرساخت دو مسیر موجود را اصلاح می‌کند. مدل TTS، فایل صدای مرجع و منطق انتخاب استراتژی معاملاتی تغییر نکرده‌اند.

## اجرا

از پوشهٔ پروژه و همان محیط فعلی:

```bash
source .venv/bin/activate
python khorshid.py       # صدای اختصاصی Pocket
# یا، پس از بستن نسخهٔ قبلی:
python khorshid_live.py  # گفتار مستقیم Gemini
```

برای نصب تازهٔ وابستگی‌های رابط و هات‌کی می‌توان از `python -m pip install -e ".[sun,hotkey]"` و برای نسخهٔ Live از `python -m pip install -e ".[live]"` استفاده کرد. فایل `requirements/requirements-live.txt` نیز اضافه شده است. این دستورها در این ارتقا اجرا نشده‌اند و محیط‌های مجازی موجود به‌روزرسانی نشده‌اند. محیط `.tts-venv` و مدل‌های اختصاصی همچنان باید موجود باشند؛ پروفایل Live جای نصب مدل Pocket نیست.

Python 3.10 برای خواندن TOML به `tomli` نیاز دارد؛ وابستگی شرطی آن در pyproject و requirements ثبت شد. خطای نحوی CLI روی 3.10 نیز برطرف شد. محیط اصلی فعلی Python 3.12 است؛ برای نصب جدید بهتر است همین نسخهٔ آزموده‌شده استفاده شود.

## تأیید عملیات

در اجرای تصویری هر دو نسخه، عملیات اثرگذار پنجرهٔ محلی تأیید دارند. پیش‌فرض پنجره «لغو» است؛ بسته‌شدن، timeout یا خطای پنجره به معنی عدم تأیید است. جزئیات کامل عملیات تا سقف مشخص نمایش داده می‌شود؛ درخواست بزرگ‌تر از سقف با جزئیات پنهان تأیید نمی‌شود.

نمونه‌ها: نوشتن/ویرایش/حذف/کپی/انتقال فایل، اجرای کد، بازکردن برنامه، کلیک و تایپ، تغییر کلیپ‌بورد، Gitهای تغییردهنده و HTTPهای تغییردهنده. گزارش ترید و درخواست توقف بدون تأیید اضافه باقی می‌مانند. شروع ترید از مسیر Runtime تأیید می‌خواهد؛ پل Live همچنان تغییرات معاملاتی و shell/Python را مسدود می‌کند.

مجوز وابسته به `interactive=True` نیست. اگر callback تأیید وجود نداشته باشد عملیات حساس اجرا نمی‌شود. در CLI تعاملی همان تأیید ترمینال استفاده می‌شود؛ `--yes` یک اجازهٔ صریح برای همان اجرای CLI است. گزینهٔ قدیمی `confirm_dangerous=false` به‌تنهایی این سیاست را غیرفعال نمی‌کند.

اگر هات‌کی را مستقلاً و بدون لانچر تصویری اجرا کنید، پنجرهٔ تأیید خودکار فعال نیست و عملیات حساس ممکن است رد شوند. مسیر پیشنهادی برای کار صوتی تصویری همین دو لانچر بالاست. API و تلگرام callback تأیید ندارند و عملیات حساس را رد می‌کنند؛ تأیید از راه دور در این مرحله اضافه نشده است.

ابزار `open_app` در لینوکس دیگر fallback برای executable و آرگومان دلخواه ندارد. برنامه‌های ثبت‌شده در desktop catalog، aliasهای موجود و مسیر شناخته‌شدهٔ MT5/Wine همچنان پشتیبانی می‌شوند. بازکردن فایل اسکریپت یا اجرایی به‌عنوان سند رد می‌شود. برای اجرای کد از ابزار اجرای کد با تأیید استفاده کنید.

این سیاست کنترل تأیید است و جای sandbox سیستم‌عامل یا احراز هویت چندکاربره را نمی‌گیرد. API فعلی برای برنامه‌های محلی مورد اعتماد است.

## تنظیمات قابل پیش‌بینی

ترتیب انتخاب فایل:

1. مسیر صریح `--config` یا `KHORSHID_CONFIG`؛ نبودن یا خراب‌بودن این فایل خطا می‌دهد و پنهانی به config دیگر برنمی‌گردد.
2. در حالت عادی `~/.ultimate-jarvis/config.toml`.
3. در نبود فایل خانگی، `configs/default.toml` پروژه و سپس مسیر پیش‌فرض بسته.

در حالت عادی، تنظیمات ذخیره‌شدهٔ داشبورد روی TOML اعمال می‌شوند و متغیرهای محیطی آخرین اولویت را دارند. config صریح تنظیمات داشبورد را کنار می‌گذارد، اما ENV همچنان اولویت دارد. یک `KhorshidConfig` آماده که از کد به Runtime بدهید دوباره با settings تغییر نمی‌کند.

انتخاب موتور به‌تنهایی مدل همان موتور را انتخاب می‌کند. انتخاب صریح مدل مرجع نهایی تعیین موتور است. مدل و موتور ناسازگار در ذخیرهٔ تنظیمات جدید رد می‌شوند. با تغییر موتور در داشبورد، فیلد مدل پاک می‌شود تا مدل موتور قبلی باقی نماند.

حالا می‌توان engine/model/voice را در تنظیمات خالی کرد تا override حذف شود. مقدار پیش‌فرض نمایشی Kore دیگر در نبود تنظیم ذخیره‌شده، صدای TOML را پنهانی override نمی‌کند. نوشتن settings با فایل موقت و جایگزینی اتمیک انجام می‌شود.

نام voice تنظیمات، صدای مرجع Pocket را عوض نمی‌کند؛ انتخاب صدای Live نیز هنوز مسیر مستقل قبلی را دارد. یکپارچه‌کردن تنظیمات صوتی مرحلهٔ بعد است.

## مسیر مستقیم ترید و ابزارها

فرمان‌های تشخیص‌داده‌شدهٔ مستقیم مثل «وضعیت معاملات» از executor، محدودیت فهرست ابزار، context حافظه و trace عبور می‌کنند. فهرست ابزار خالی واقعاً به معنی بدون ابزار است. فرمان مستقیم دیگر محدودیت config را دور نمی‌زند.

برای عملیات نیازمند تأیید، retry و fallback خودکار روی شکست غیرفعال شده‌اند تا یک تغییر با نتیجهٔ نامطمئن دوباره اجرا نشود. timeout همچنان تضمین پایان thread در حال اجرا نیست؛ این محدودیت در این مرحله حذف نشده است.

## API محلی

`serve` اتصال به host عمومی مثل `0.0.0.0` را نمی‌پذیرد. Host و Originهای غیرمحلی رد می‌شوند و POST باید JSON باشد. بدنهٔ JSON نامعتبر، غیرآبجکت یا بزرگ‌تر از یک مگابایت رد می‌شود. این محافظت مرورگری برای کاهش درخواست ناخواسته است؛ توکن احراز هویت و دسترسی از دستگاه دیگر در این نسخه پیاده نشده‌اند.

## آزمون‌ها و موارد باقی‌مانده

تست‌های جدید شامل ماتریس اجازه/رد، تغییر واقعی فایل در پوشهٔ موقت، جلوگیری از retry/fallback عملیات اثرگذار، محدودیت launcher، مسیر مستقیم ترید با ابزار ساختگی، تقدم تنظیمات، حذف override، خطای config، پل Live و محدودیت API هستند. تست‌های قبلیِ نوشتن فایل و اجرای کد، تأیید ساختگی صریح دریافت کرده‌اند.

برای اجرای ایزولهٔ مجموعهٔ آفلاین:

```bash
.venv/bin/python tests/run_offline.py
```

این اجرا به سوکت localhost نیاز دارد، تنظیمات و دیتابیس موقت می‌سازد و درخواست urllib به اینترنت خارجی را مسدود می‌کند. تست‌های نیازمند سخت‌افزار یا سرویس واقعی صریحاً کنار گذاشته می‌شوند.

نتیجهٔ نهایی این مرحله: **۱۳۴ تست موفق، ۶ تست زنده skipped و ۸ تست وابسته به سخت‌افزار/سرویس کنارگذاشته‌شده**؛ اجرای نهایی بدون هشدار حافظه تمام شد. بررسی نحو فایل‌های پایتون و اجرای `CLI --help` با Python 3.10 نیز موفق بود؛ سازگاری کامل همهٔ وابستگی‌ها روی 3.10 آزموده نشده است.

تست نمایش واقعی پنجره و آزمون شنیداری دو مسیر باید روی دسکتاپ فعال انجام شود؛ مدل صدا یا میکروفون برای تست خودکار روشن نشده است. کیفیت مدل‌های ابری، سفارش واقعی MT5 و سیاست‌های سمت EA جزو تأیید این مرحله نیستند.

کارهای مرحلهٔ بعد: حافظهٔ خودکار Live، قطع پاسخ و reconnect، آزادکردن callback هات‌کی از پردازش طولانی، کامل‌کردن schema/context و گزارش دقیق‌تر هزینه/موتور فعال.

## پاک‌سازی فایل‌های بدون استفاده

۱۸ فایل از مسیر پروژه حذف شدند: دو کپی دقیق `tts_session_smooth.py` و `tts_text_natural.py`، پنج نسخهٔ `.backup`/`.before`، شش فایل پوشهٔ قدیمی `patch`، نصب‌کنندهٔ قدیمی `apply_fast_tts.py` با manifest ناموجود، مسیر تک‌اجرای قدیمی `pocket_farsi_tts.py` و نمونهٔ `test_farsi_v2.py`، فایل راهنمای نسخهٔ ناموجود `xorshid_setup.txt` و فایل خالی `subprocess`.

ارجاع بلااستفادهٔ PocketTTS به اسکریپت قدیمی و سه import بدون استفاده نیز حذف شدند. کلاس PocketTTS به‌عنوان رابط سازگار با worker فعلی باقی مانده است.

دو لانچر، worker فعال TTS، نرمال‌ساز فارسی، فایل‌های صدا و تصویر، محیط‌های مجازی، تست‌های فعلی، داده‌های حافظه/ترید و پشتیبان‌های تاریخی دارای سورس MT5 حفظ شدند. `ultimate_khorshid/interface/khorshid_live_trial.py` و `ultimate_khorshid/interface/khorshid_live_pitch.py` وابستگی نسخهٔ فعلی Live هستند و حذف نشدند.

پیش از حذف، آرشیو بازیابی و manifest شامل SHA-256 همهٔ ۱۸ فایل ساخته و محتویات آن بررسی شد: `/tmp/khorshid-cleanup-u3228rg2/removed-files.tar.gz`. مسیر `/tmp` موقتی است؛ برای نگهداری بلندمدت آرشیو را به محل دلخواه منتقل کنید.
