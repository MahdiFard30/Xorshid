# مرحلهٔ چهارم — ورودی ابزارها و Context مکالمات بلند

تاریخ: ۲۰۲۶-۱۰-۱۷. اجرای `khorshid.py` و `khorshid_live.py` و صدای شخصی مانند قبل است. این مرحله اعتبارسنج مشترک ابزارها و مدیریت پیام‌های ایجنت‌های درخواست/پاسخ را تغییر می‌دهد؛ مدیریت پنجرهٔ نشست بومی Gemini Live همچنان در سرویس انجام می‌شود.

## اعتبارسنجی ورودی

اعتبارسنج مشترک پیش از تأیید و اجرای ابزار، محدودیت‌های اعلام‌شده در schema همان ابزار را بررسی می‌کند. مقدارها خودکار به نوع دیگری تبدیل نمی‌شوند و محدودیتی که ابزار اعلام نکرده باشد خودکار اضافه نمی‌شود.

- مقدارهای boolean دیگر به‌عنوان عدد پذیرفته نمی‌شوند؛ مثلاً `limit=true` برای فیلد integer رد می‌شود. مطابق [تعریف عدد در JSON Schema](https://json-schema.org/understanding-json-schema/reference/numeric)، عدد صحیحی مثل `1.0` از نوع integer محسوب می‌شود.
- کمینه/بیشینه و مرزهای انحصاری عدد، مضرب عددی، طول رشته، الگوی رشته، تعداد اعضای آرایه و آبجکت بررسی می‌شوند.
- تمام اعضای آرایه بررسی می‌شوند؛ سقف خاموش ۵۰ عضو حذف شده است. [تعریف items](https://json-schema.org/understanding-json-schema/reference/array) نیز بررسی همهٔ اعضای آرایه را تعیین می‌کند.
- فیلدهای لازم، enum، const، فیلد اضافی طبق additionalProperties، یکتایی اعضا، نوع‌های nullable و schemaهای true/false پشتیبانی می‌شوند. در مقایسه‌ها `true` با `1` برابر گرفته نمی‌شود.
- ترکیب‌های allOf، anyOf، oneOf و not بررسی می‌شوند؛ معنای شرط‌ها مطابق [مرجع ترکیب schema](https://json-schema.org/understanding-json-schema/reference/combining) است.
- NaN و Infinity، حتی در بخش بدون محدودیت خاص، ورودی JSON معتبر محسوب نمی‌شوند. ارجاع `$ref` و `$dynamicRef` پشتیبانی نمی‌شود و در محل ارجاع خطا برمی‌گردد؛ شبکه‌ای برای دریافت schema استفاده نمی‌شود.

این پیاده‌سازی یک زیرمجموعهٔ محلی است، نه اعتبارسنج کامل تمام نسخه‌های JSON Schema. امکاناتی مانند format، patternProperties، prefixItems و قواعد شرطی if/then/else پیاده نشده‌اند؛ schema ابزار تازه باید با قابلیت‌های پشتیبانی‌شده نوشته شود.

## مکالمات بلند

پیش از فراخوانی موتور، برآورد اندازهٔ پیام‌ها اکنون علاوه بر متن، آرگومان‌ها، نام‌ها، شناسه‌ها و ساختار فراخوانی ابزار را هم حساب می‌کند. این همچنان تخمین پیام‌هاست، نه شمارش قطعی توکن‌های سرویس یا تضمین کل پنجره با تعریف ابزارها و خروجی رزروشدهٔ مدل.

حذف سابقه در مرز نوبت کاربر انجام می‌شود: درخواست و تبادل‌های ابزار مربوط به آن با هم می‌مانند یا با هم کنار گذاشته می‌شوند. نوبت آخر و systemها حفظ می‌شوند. نتیجهٔ ابزار بر اثر برش از فراخوانی‌اش جدا نمی‌شود.

اگر نوبت آخر بزرگ باشد، ابتدا متن خروجی ابزارها و متن دستیار با علامت `…[trimmed]` کوتاه می‌شود. متن درخواست کاربر تا حد امکان حفظ می‌شود و فقط در صورت نیاز کوتاه می‌شود. تعداد پیام‌های همان نوبت، آرگومان ابزار، شناسهٔ فراخوانی و ارتباط نتیجه تغییر نمی‌کنند. محتوای چندرسانه‌ای به رشتهٔ ناقص تبدیل نمی‌شود. اگر systemها یا ساختار غیرقابل‌برش در بودجه جا نشوند، `ContextBudgetError` برمی‌گردد؛ پیام نامعتبر یا بزرگ‌تر از بودجهٔ تخمینی فرستاده نمی‌شود.

این تغییر روی نسخهٔ ارسالی پیام‌ها کار می‌کند و متن اصلی سابقه را بازنویسی نمی‌کند. حافظهٔ پایدار و استخراج facts تغییر نکرده‌اند.

تابع خلاصه‌سازی موجود نیز systemها و نوبت کامل آخر را نگه می‌دارد؛ خطای موتور یا خلاصهٔ خالی باعث حذف تاریخچه نمی‌شود. این تابع همچنان خودکار در مسیر عادی فعال نشده است؛ برای این مرحله تماس یا هزینهٔ تازهٔ خلاصه‌سازی اضافه نشده است.

## آزمون

۵۳ تست جدید شامل مرزهای عددی و نوع‌ها، عضو بعد از پنجاهم، خطای تو‌در‌تو، جلوگیری از اجرا و تأیید برای ورودی نامعتبر، حفظ فراخوانی/نتیجه، خروجی بلند ابزار، آرگومان بزرگ، محتوای چندرسانه‌ای و خطای خلاصه‌سازی هستند.

```bash
.venv/bin/python tests/run_offline.py
```

نتیجهٔ نهایی: **۲۴۳ تست موفق، ۶ skipped و ۸ deselected**. بررسی نحو فایل‌های این مرحله با Python 3.10 نیز موفق بود.

تست‌ها از موتورهای ساختگی، ابزار بدون اثر و وضعیت موقت استفاده می‌کنند؛ در این مرحله تماس زنده با Gemini، تغییر مدل صدا یا عملیات واقعی متاتریدر انجام نشده است.
